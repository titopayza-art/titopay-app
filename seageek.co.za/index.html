How it works

Your systems call one SeaGeek API. We send each request to a licensed upstream provider, and we can change providers without changing the API you use.

  • One key for every productOrganisations, users, roles and API keys are managed in one place.
  • Signed webhooks, safe retriesEvery event is signed. Idempotency keys stop a retry from sending twice.
  • A separate sandboxTest keys and test data, with nothing delivered and nothing billed.
  • Itemised usage in randEvery metered request shows on your usage report, with alerts before you go over budget.
# Send an OTP by SMS
curl https://api.seageek.co.za/v1/sms/messages \
  -H "Authorization: Bearer $SEAGEEK_KEY" \
  -H "Idempotency-Key: order-10294-otp" \
  -d '{
    "to": "+27821234567",
    "from": "SeaGeek",
    "body": "Your verification code is 482913"
  }'
import { SeaGeek } from "@seageek/node";

const sg = new SeaGeek(process.env.SEAGEEK_KEY);

const msg = await sg.sms.send({
  to: "+27821234567",
  from: "SeaGeek",
  body: "Your verification code is 482913",
}, { idempotencyKey: "order-10294-otp" });
from seageek import SeaGeek

Security and compliance

Messaging and identity checks involve personal information. No product takes live customers until it has passed its security and operational checks.

Security

  • Encryption in transit and at rest
  • Each customer's data kept separate
  • Role-based access and audit logs
  • Signed webhooks
  • Rate limits and abuse monitoring
  • Separate sandbox and production
  • Tested backups
  • Regular penetration tests
  • Reviews of admin access
  • A written incident response plan

Regulation

POPIALawful processing, collecting only what's needed, set retention periods, data-subject requests and controls on cross-border transfers.
ICASALicensing assessed against the telecoms services we actually provide.
ConsentOpt-outs and suppression lists applied automatically. Customers agree to use messaging lawfully.
FIC ActVerification products launch only with licensed data sources and legal sign-off.
AIModels are tested before release, sensitive data is protected, and a person approves important decisions.
