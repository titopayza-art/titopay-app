01 · Quickstart

Your first message in three steps

Step 1

Create an account

Sign up on the dashboard and get a sandbox key right away. No card needed.

Step 2

Call the sandbox

Send test requests to sandbox.seageek.co.za. Nothing is delivered and nothing is billed.

Step 3

Go live

Verify your business, switch to a live key and send real traffic.

02 · Authentication

Bearer keys, scoped by role

Every request carries an API key in the Authorization header. Keys belong to an organisation, can be limited to specific products and permissions, and can be rotated without downtime. Test keys start with sg_test_ and live keys with sg_live_. Keep keys on your server and never put them in client-side code.

04 · Idempotency

Retry safely, send once

Add an Idempotency-Key header to any POST. If a network error makes you retry, SeaGeek returns the original response and doesn't send again. Keys are stored for 24 hours. A good key is your own record ID plus an action, such as order-10294-otp.

05 · Webhooks

Signed events with automatic retries

Delivery receipts, bounces, replies and verification results arrive as webhooks. Each request carries a SeaGeek-Signature header: an HMAC-SHA256 of the timestamp and raw body, using your endpoint secret. If your endpoint doesn't return a 2xx, we retry with exponential backoff for up to 24 hours.

verify-webhook.js
import crypto from "node:crypto";

export function verifySeaGeek(rawBody, header, secret) {
  // header: "t=1767225600,v1=5f2b…"
  const parts = Object.fromEntries(header.split(",").map(p => p.split("=")));
  const expected = crypto.createHmac("sha256", secret)
    .update(`${parts.t}.${rawBody}`).digest("hex");
  const fresh = Math.abs(Date.now() / 1000 - Number(parts.t)) < 300;
  return fresh && crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(parts.v1));
}
06 · Errors & limits

Predictable failures

Errors use standard HTTP status codes and a consistent JSON body with type, code, message and a request_id to quote to support. Rate-limit headers come with every response.

StatusTypeMeaning
400invalid_requestA parameter is missing or malformed
401authentication_errorThe key is missing, revoked or for the wrong environment
402insufficient_balancePrepaid balance or credit limit reached
403permission_errorThe key's role doesn't allow this product or action
409idempotency_conflictThe same key was reused with a different payload
422compliance_blockOpt-out, suppression or sender rules stopped the send
429rate_limitedToo many requests. Wait for the time in Retry-After
5xxapi_errorA problem on our side. Safe to retry with your idempotency key
