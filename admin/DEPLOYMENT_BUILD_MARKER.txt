TitoPay Admin build: admin-console-v86-20260815

This build and v85 together harden the Security Content page shipped in v84.
Nothing else on the console changes.

v86 (this build), from review of v85:
  - The provenance line no longer fails open. It tested a positive flag, so an
    API that does not send "stored" (anything before build 26) was read as
    "nobody has edited this yet" and printed over a colleague's live wording,
    which is the exact mistake the line exists to prevent. A missing field now
    reports that the API cannot tell us.
  - Retry load says what happened. Against an API that is still down it
    repainted byte-identical markup with no message, indistinguishable from a
    dead button.
  - The customer preview draws the warning card in the app's warning pink
    instead of the console's blue. The panel promises "how the card reads in the
    TitoPay app", so an operator judging whether a warning reads urgently enough
    has to be looking at the real thing.

v85, carried in this build:
  - Save is DISABLED when the stored content could not be read. v84 showed a
    warning next to a working Save button, so the guard against overwriting an
    unread version was advice rather than a rule. A "Retry load" button takes
    its place, and pressing Enter in a field is refused for the same reason.
  - The icon picker offers exactly the icons the API accepts. v84 offered 16 of
    them while the API accepted 84, so opening content whose icon came from
    outside those 16 and pressing Save quietly rewrote it to "shield". Both
    sides now carry the same curated list of 29, spelled out for the operator
    ("Message Check" rather than "message-check"), and the API test suite fails
    if the two lists drift apart.
  - The page states whether it is showing saved copy or the wording TitoPay
    ships with, and when a person last saved it and who.
