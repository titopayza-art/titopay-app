TitoPay Admin build: admin-console-v85-20260815

This build hardens the Security Content page shipped in v84. Nothing else on
the console changes.

  - Save is DISABLED when the stored content could not be read. v84 showed a
    warning next to a working Save button, so the guard against overwriting an
    unread version was advice rather than a rule. A "Retry load" button takes
    its place, and pressing Enter in a field is refused for the same reason.
  - The icon picker offers exactly the icons the API accepts. v84 offered 16 of
    them while the API accepted 84, so opening content whose icon came from
    outside those 16 and pressing Save quietly rewrote it to "shield". Both
    sides now carry the same curated list of 29, spelled out for the operator
    ("Message Check" rather than "message-check"), and the API test suite fails
    if the two lists drift apart.
  - The page states whether it is showing saved copy or the wording TitoPay
    ships with, and when a person last saved it and who. Those two states
    looked identical on screen in v84, so an operator could not tell whether
    they were revising a colleague's work or writing the first version.

Upload notes:
  - REQUIRES api.zip build 26. v84 saves would store the copy and then answer
    500, because the audit write put the settings key into a UUID column. The
    console reported an error over a change that had in fact been made.
  - Asset stamp moves from admin-console-v84 to admin-console-v85 across all
    66 HTML files, so operators cannot be served a cached admin.js.
  - No new directories and no new endpoints; /security-content/ already exists
    from v84.
  - Replace the whole admin directory as usual. Nothing under api/ or the
    website bundle is touched.
