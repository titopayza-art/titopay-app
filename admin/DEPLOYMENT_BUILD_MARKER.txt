TitoPay Admin build: admin-console-v92-20260816

v89 (this build): when a console page breaks, this console now tells you why.

  THE PROBLEM IT SOLVES. The console answers "Unable to complete this admin
  action" for every server-side failure, on purpose: an operator screen must
  not print database errors to whoever is looking at it. That is right for the
  console and useless for the person who has to fix it, and the tool that put
  the detail back was a script you needed SSH to run. SSH is exactly what you
  do not have when a page breaks at two in the morning.

  DATABASE HEALTH IS NOW A DIAGNOSIS. It shows the same report that
  `npm run db:diagnose` prints, from the same service in the API, so the two
  can never drift apart:

    - which tables each console page needs, and which are missing, with the
      page named so a missing row says what it will break
    - the queries the failing panels actually run, with the REAL Postgres
      error and its code
    - the save statements behind the buttons that say nothing useful, so
      "Save Maintenance Mode did nothing" stops being a mystery
    - the shape of platform_settings on THIS database: its columns and how
      many foreign keys it has. Five files declare that table and they
      disagree, and whichever ran first on a given database is the one that
      exists, forever
    - which provider supplies which capability, and which are not contracted

  It only reads. The save probes are real writes, because a read that works
  while a save fails is the whole shape of the problem, but every one runs
  inside a transaction that is always rolled back. Running it changes nothing.

  IT ALSO STOPPED LYING. Database Health used to check a hardcoded list of
  fifteen tables, written when the platform was much smaller, against a schema
  now past a hundred and seventy. It could report everything green while the
  tables behind a broken page were missing. It now checks the same map the
  diagnosis uses, so the list grows with the platform.

  THE TOPBAR SAYS WHICH API BUILD YOU ARE TALKING TO. GET /health has reported
  the build since it was added and nothing ever read it. The chip is quiet when
  the API is current and red when it is behind what this console needs, with
  both numbers and what to do about it.
