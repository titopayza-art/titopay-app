TitoPay Admin
Build: admin-console-v55
Date: 2026-08-06

v55 - Alert Centre. The platform events that were flooding the owner's inbox
as emails - sign-ins recorded, failed attempts, fraud flags, pending KYC,
waiting customers, failed transactions - now live inside the console.

  - A bell in the topbar of every page carries the unread count. Its panel
    shows the most recent alerts and marks all read in one click.
  - The new Alerts module (sidebar, under Dashboard) is the full centre:
    severity tabs with counts, category filter, unread-only view, pagination,
    mark all read, and every alert links to the module that owns the event.
  - Alerts are derived live from the security, audit, compliance, support,
    transaction, system-health and merchant modules - the same events the
    emails describe. Nothing is invented; a source that does not answer
    contributes no alerts. The feed refreshes every two minutes while the
    console is open.
  - Read state is stored per browser. The API has no alert-read endpoint yet,
    and the page says so rather than pretending the state is shared.
  - The alert emails themselves are sent by the TitoPay API, not this console.
    Now that the events are visible here, the API's notification sender can be
    switched off for routine sign-in mail without losing anything.
  - The CI gate grew to cover it: the alerts route renders, the bell carries
    an unread badge, the panel opens, and mark-all-read clears the badge.

v54 - Bank-grade hardening beneath the interface, and the console gains a
permanent regression gate. No console page behaviour changed.

  - Transport and headers. The .htaccess now sends Strict-Transport-Security,
    Cross-Origin-Opener-Policy and Cross-Origin-Resource-Policy alongside the
    existing headers, denies dotfiles and repository documentation, and its
    Content-Security-Policy drops unsafe-inline for styles and gains the
    wss://api.titopay.co.za entry the pages already declared - without it, a
    host with mod_headers active would have blocked the support chat socket.
  - The sign-in page's own CSP also drops unsafe-inline: no page in the
    console now permits inline styles.
  - Failure surface. Branded 403 and 404 pages replace the server defaults,
    wired through ErrorDocument, with routes back to the dashboard and sign-in.
    robots.txt disallows everything, matching the noindex headers.
  - Release integrity is now enforced, not assumed: a committed test gate
    (tests/admin in the repository, run by CI on every push) verifies one
    version string across all pages, the version file and the deployment
    marker, then drives the real console in Chromium - credential sign-in to
    the dashboard, all 38 routes rendering, the table layer, the analytics
    permission gate and a zero-console-error run.

v53 - The sign-in page is finished to the same enterprise standard as the
console behind it. Presentation only: every element admin.js binds to - the
sign-in form, password reveal, Caps Lock hint, forgot-password card, Email OTP
challenge, status line and environment badge - keeps its exact id, class and
attribute, and the full flow was exercised end to end after the change.

  - The form now sits in an elevated card on a softly tinted panel, with the
    page's entrance rise, so the credentials surface reads as the protected
    object on the page rather than fields floating on white.
  - A trust strip under the card states the session protections that are
    actually in force: encrypted connection, role-based access, audited
    actions. Nothing is claimed that the platform does not do.
  - The brand panel gains a fine engineering grid over the gradient and the
    security points become icon chips. The logo artwork is framed as a
    deliberate plate in both themes instead of a white box on the tint.
  - The footer now carries the console build identity, so the version that is
    live is readable from the sign-in screen.
  - Verified: sign-in reaches the dashboard, the OTP challenge injects and
    focuses, the reset card toggles, the password reveal works, identifier is
    autofocused, both themes render, and there is no horizontal overflow at
    1280, 1024, 820 or 390 wide.

v52 - Enterprise UI/UX pass. Presentation only: no endpoint, permission,
route, payload or business rule was changed, and a control-by-control
comparison of all 38 routes before and after shows zero removals.

  - Design system. A two-stop elevation ramp replaces the single flat shadow,
    radii and spacing move onto one scale, headings and figures tighten, and
    the muted ink was darkened to clear WCAG AA on card surfaces. Buttons gain
    press feedback and a consistent disabled state; a bare submit button in the
    filter rows no longer renders as browser chrome.
  - Navigation. The rail collapses to icons and remembers the choice per
    browser. Nothing is removed when it does: every item keeps its route, icon
    and accessible name, and the label moves to a tooltip. The state is ignored
    below the tablet breakpoint, where the rail is already a drawer. Escape
    closes the drawer.
  - Tables. Every table in the console gains sortable headers with aria-sort
    and a third click that restores the module's own order, a row filter with a
    live count, bulk selection with select-all, per-table export of what is on
    screen, column resizing, and a sticky header that reads as a layer. The
    layer works on the rendered table through a MutationObserver, so no module
    was modified to receive it and modules that re-render keep it.
  - Prioritisation by colour. A row carrying a red or orange status now shows a
    matching accent on its leading edge, so high-risk compliance reviews,
    flagged transactions and queues waiting on an agent are visible without
    reading. The accent is drawn from the status the module already rendered.
  - Dashboard. Keeps the four figures and the endpoint that produced them, and
    adds wallet float, active sessions, pending KYC, open tickets, merchant
    onboarding, flagged security events, a platform health panel covering API,
    database, providers and sessions, and a live activity feed from the audit
    log. The first paint still comes from the overview endpoint alone;
    everything else arrives after it and never blocks it. A source that does
    not answer leaves a dash.
  - States and feedback. Toasts carry a tone and an icon, inferred from the
    message, so a confirmation and a failure no longer look identical. Empty
    tables explain themselves. A progress line runs under the topbar while a
    module loads. Content settles in rather than snapping, and every animation
    is dropped under prefers-reduced-motion.
  - Accessibility. A visible focus ring is guaranteed console-wide, including
    the rail. Required fields are marked on the label. Pointer targets reach
    44px below the tablet breakpoint. Sortable headers are keyboard operable
    and announce their state.
  - Verified: 38 routes render, no console errors, no horizontal overflow at
    1440, 1280, 1024, 820 or 768, both themes, and page-load timings unchanged
    within run-to-run noise apart from the dashboard, which paints about 30ms
    later because the board is larger.

v51 - Enterprise Analytics. A new Analytics module joins the Operations
group in the sidebar with eight reporting sections: Executive, Financial,
Users, Transactions, Merchants, Fraud & Security, Support and System. It
carries KPI cards with period-on-period growth, line, area, bar, ranked bar,
donut and heat-map charts, paginated tables, date-range and dimension filters,
and PDF, Excel and CSV export.

  - The module is a separate file, assets/admin-analytics.js, imported the
    first time an operator opens Analytics. Every other console page loads
    exactly the JavaScript it loaded in v50.
  - Analytics reads existing admin endpoints only. No endpoint, permission,
    payload or database structure was changed. If the optional
    GET /admin/analytics/overview endpoint is added later, the module picks it
    up automatically; without it the page works from the modules already live.
  - A metric the API does not carry shows a dash and is listed in that
    section's Data coverage card. Nothing is estimated or simulated.
  - Access needs an analytics or reporting permission. Full-access and
    platform-owner roles keep the access they already had, and no other
    module's access rules were touched.
  - Aggregates are cached for sixty seconds per range and filter set, the
    transaction pull is bounded by the range and a row limit, and long tables
    paginate at ten rows.

v35 - Global Search decluttered; RBAC becomes editable
  - Global Search showed four result tables and a record card at once. It now
    has one result list at a time behind tabs (People, Businesses, Wallets,
    Transactions) with match counts, and opening a record replaces the results
    with that record and a "Back to results" control.
  - RBAC / Permissions is now an editor, not a read-only matrix. The platform
    owner and the developer role can change any role's permissions, create new
    roles and delete custom ones. Requires the matching API package.
