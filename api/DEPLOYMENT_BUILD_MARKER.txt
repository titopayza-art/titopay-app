API changes in this build:
  - ticketing-service: purchaseTickets loads the platform revenue wallet only
    when a fee is actually owed (fee > 0 ? load : null), matching every other
    money path. A free ticket now moves no money and never requires the
    revenue wallet, so a free purchase can no longer 500 on an environment
    where the revenue wallet is not provisioned.
  - ticketing routes: new read-only GET
    /v1/ticketing/business/events/:id/attendance, gated by the "scan"
    permission (organiser or assigned scanner), returns { scanned, total }.

Migrations to run: none new in this build.
